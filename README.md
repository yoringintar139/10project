# 10project
제가 10월달에 할 프로젝트는 운동 추천 입니다. 이 프로젝트는 사람들이 운동을 할려고 할떄 자신의 몸에 맞게 운동을 추천 해주는 프로젝트를 만들려고 합니다. 이 앱의 사용 대상자는 운동을 열심히 하려는 사람,다이어트를 하려는 사람등을 위해 만들었습니다.

---

## PRD (Product Requirements Document)

# 1.문제정의
1. 사람들은 운동을 잘하고 싶으데 자신에게 자신에게 맞는 운동인지 잘 몰라 시간으 많이 소비 합니다. 그래서 저는 자신에게 맞는 운동을 찾아주는 앱을 만들 것 입니다.
2. 헬스장이나 인터넷에서 찾은 운동이 자신의 체형, 체력, 건강 상태와 맞지 않아 부상을 당하거나 중도 포기하는 경우가 많습니다.
3. 많은 운동 정보가 넘쳐나지만, "나"에게 맞는 운동을 추려주는 서비스가 부족합니다.

# 2.페르소나
1. 살을 빼고 싶지만 자신의 몸에 맞는 운동을 못 찾아 하기 힘든 운동을 하여 힘든 사람
   - 예: 체중이 많이 나가 고강도 유산소가 부담스러운 다이어터
2. 운동을 잘하고 싶지만 자신이 잘할수 있는 운동을 몰라 힘든 사람
   - 예: 운동 초보자로서 어떤 종목부터 시작해야 할지 모르는 사람
3. 지병(허리/무릎 등)이 있어 운동 선택에 제약이 있는 사람

# 3.기대효과 
1. 사람들이 자신에게 맞는 운동을하여 건강해지게됨
2. 무리한 운동으로 인한 부상 위험 감소
3. 운동 초보자의 진입 장벽을 낮춰 꾸준한 운동 습관 형성에 도움

# 3-1.성공 지표(KPI)
1. 주간 활성 사용자 수(WAU): 신체 정보를 입력하고 추천을 받은 사용자 수
2. 추천 수락률: 추천받은 운동을 실제로 선택/실행한 비율
3. 재방문율: 일정 기간 내 다시 접속해 추천을 받은 사용자 비율
4. 평균 운동 완료 시간: 타이머 기능을 끝까지 사용한 세션 비율

# 4.핵심기능 
1. 자신의 몸상태(체중,병이 있는지,키 등)에 를 적고 운동을 추천 해줌
   - 입력 항목: 체중, 키, 나이, 지병 여부(선택), 운동 경험 수준
2. 어떤 종류에 운동을 하고 싶은지 선택(예: 싸움,얼음,물 등 )
   - 예: 격투기 계열, 수상 운동, 겨울 스포츠 등 카테고리별 선택
3. 간단한 운동,힘든 운동 선택 
   - 난이도(쉬움/보통/어려움)를 선택해 추천 결과를 조절

# 5.부가기능
1. 건강 지킴이 앱으로 갈수 있는 주소 만들기
   - 외부 건강관리 앱으로 연결되는 바로가기 링크 제공
2. 몇 시간,몇 분 정도 할지 시간을 정하고 추천 받기
   - 가용 시간(예: 20분, 40분, 1시간)을 입력하면 그에 맞는 운동 루틴 추천
3. 운동 시간 타이머 마추기
   - 추천받은 운동을 실행할 때 사용할 수 있는 타이머/알림 기능

# 6.핵심화면
1. 운동 강도를 설정하는 버튼
2. 자신의 몸상태 작성창
3. 자신이 원하는 종류의 운동 선택창

# 6-1.타겟 플랫폼
1. 웹 (별도 앱 설치 없이 브라우저에서 바로 사용)

# 7.개발시 고려 사항 (기획)
1. 작성자에게 맞는 운동인지 잘 확인
2. 입력한 신체 정보(체중,키,지병 등)와 선택한 운동 종류/강도가 서로 모순되지 않는지 검증
   - 예: 지병이 있는 사용자가 고강도 운동을 선택하면 경고 메시지 표시
3. 사용자가 입력을 빠뜨리거나 잘못 입력했을 때 안내 메시지 제공

# 8.보안 (기획)
1. 체중,키,지병 여부 등 민감한 신체 정보는 암호화하여 저장
2. 비정상적인 수치(음수,비현실적인 값 등) 입력을 막는 유효성 검사 적용
3. 운동 추천에 필요한 최소한의 개인정보만 수집
4. 개인정보 수집/이용 목적을 사용자에게 명확히 고지하고 동의 절차 마련

# 9.디자인
1. 네온 그린을 메인 컬러로 사용
2. 다크 배경 + 네온 그린 포인트로 활력/운동 이미지 강조

# 10.예상 일정
1. 한달(일주일에 2시간 총 8시간)
2. 1주차: 요구사항 정리 및 화면 설계
3. 2~3주차: 핵심 기능 구현(신체 정보 입력, 운동 선택, 추천 로직)
4. 4주차: 부가기능 및 테스트, 마무리

## TRD (Technical Requirements Document)

# 1.시스템 개요
- 사용자가 자신의 신체 정보와 운동 선호도를 입력하면, 조건에 맞는 운동을 추천해주는 앱/서비스
- 클라이언트(입력 폼/화면) → 추천 로직(서버 또는 클라이언트 내 규칙 기반 필터링) → 운동 데이터 저장소(DB) 구조

# 2.기술 스택
1. 프론트엔드: React (웹 SPA)
2. 백엔드: Node.js + Express
3. 데이터베이스: SQLite (초기 MVP 규모에 적합, 추후 사용자 증가 시 PostgreSQL로 전환 고려)
4. 인증/세션: 회원가입 없이 쓰는 경우 로컬 저장(local storage) 활용 검토, 추후 계정 기능 추가 시 토큰 기반 인증 고려

# 3.데이터 모델 (초안)
1. 사용자(User)
   - 체중, 키, 지병 여부, 선호 운동 종류, 운동 강도 선호도, 가용 시간
2. 운동(Exercise)
   - 종류, 난이도(간단/힘든), 적합 조건(체중/키/지병 범위), 소요 시간, 운동 설명/영상 링크(선택)

# 4.핵심 기능 구현 방안
1. 체성분/신체정보 입력 폼 → 사용자 데이터 저장
   - 프론트엔드 폼 + 클라이언트 측 1차 유효성 검사
2. 운동 종류 선택 UI → 필터 조건으로 사용
3. 간단한/힘든 운동 선택 → 난이도 필터링
4. 추천 로직: 입력된 신체 정보 + 선택 조건을 기반으로 운동 DB에서 필터링하여 추천 (초기에는 규칙 기반, 추후 고도화 가능)
   - 1단계: 지병/체형 조건으로 1차 필터링
   - 2단계: 선호 종류/난이도/가용 시간으로 2차 필터링
   - 3단계: 필터링 결과 중 랜덤 또는 우선순위 기반으로 추천 목록 제공

# 5.부가기능 구현 방안
1. 외부 "건강 지킴이 앱" 연동용 딥링크/URL 설계
2. 시간 설정 입력 → 추천 로직에 소요 시간 조건 추가
3. 운동 타이머 기능 (프론트엔드 타이머 컴포넌트)
   - 카운트다운/알림(사운드, 진동) 기능 포함 검토

# 6.화면 구성 (기술 관점)
1. 운동 강도 설정 버튼 → 상태(state)로 관리
2. 신체 정보 입력 화면 → 폼 검증(validation) 필요
3. 운동 종류 선택 화면 → 다중 선택 UI 컴포넌트
4. 추천 결과 화면 → 리스트/카드 형태로 운동 목록 표시

# 7.개발시 고려 사항 (기술)
1. 입력된 신체 정보와 추천 로직 간의 정합성 검증 (잘못된 운동 추천 방지)
2. 입력값 유효성 검사 (비정상적인 체중/키 값 등 방어)
3. 입력 누락/오류 시 사용자 안내 메시지 처리 로직
4. 추천 결과가 없을 경우(조건이 너무 좁은 경우)에 대한 예외 처리

# 8.보안 (기술)
1. 사용자 신체 정보(체중, 지병 여부 등) 는 민감정보로 분류 → 저장 시 암호화 고려
2. 개인정보 수집 최소화 원칙 적용
3. 서버/클라이언트 단 입력값 유효성 검사(비정상 수치 방어) 적용
4. 통신 구간 암호화(HTTPS) 적용 검토

# 9.디자인 가이드 연동
1. 네온 그린 컬러를 기준으로 한 디자인 시스템/스타일 가이드 적용
2. 다크 모드 배경을 기본값으로 하여 네온 컬러의 가독성 확보

# 10.일정 및 리스크
1. 개발 기간: 한달(일주일 2시간, 총 8시간) — 기능 범위가 큰 경우 일정 리스크 있음, MVP 범위 축소 고려 필요
2. 리스크: 추천 로직의 정확도 검증 시간 부족 가능성 → 초기에는 단순 규칙 기반으로 범위를 좁혀 개발

## 로컬 실행

Node.js 24 이상이 필요합니다. 저장소 루트에서 의존성을 설치하고 운동 카탈로그를 준비합니다.

```bash
npm install
npm run catalog:init --workspace=@fitmotion/exercise-api
```

API와 웹 앱은 각각 별도 터미널에서 실행합니다.

```bash
npm run dev --workspace=@fitmotion/exercise-api
npm run dev --workspace=@fitmotion/exercise-web
```

웹 앱은 Vite가 출력하는 로컬 주소에서 열고, API는 `http://localhost:3000`에서 실행됩니다. `npm run build`와 `npm test`는 전체 workspace를 검증합니다. 개인 운동 프로필은 브라우저 메모리에서만 사용되며 API와 SQLite 카탈로그에는 저장되지 않습니다.
